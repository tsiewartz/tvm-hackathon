Semantic views

✓ Do

  • Ask "how would I explain this to a business stakeholder?"
  • Explain TVM-specific terms, abbreviations and codes (e.g. FI = Finland)
  • Give every view at least one date dimension and one fact. A view with only COUNT(*) is too thin to answer well
  • Use metrics for rates, averages and distinct counts, and derived metrics for ratios
  • Use module_custom_instructions.sql_generation for defaults: period, currency, fiscal calendar
  • Use module_custom_instructions.question_categorization to decline or clarify
  • Use Cortex Search for free-text values with many distinct values (titles, names)

✗ Don't

  • Build one "all tables" semantic view
  • Include every column
  • Auto-generate synonyms
  • Patch a weak model with dozens of verified queries
  • Start in a domain that needs 100% accuracy
  • Put real PII in sample values (they aren't masked)
  • Use Cortex Search on numbers, dates or long free-text fields

Agents

✓ Do

  • Name the audience and the decision in the instructions
  • Make tool descriptions specific: they're how the agent picks a tool
  • Have the agent state its assumptions (period, filters)
  • Set a budget (seconds and tokens) and a query timeout
  • Add 3–5 sample questions that you know work
  • Test as your dev role, not ACCOUNTADMIN, and as a user would ask

✗ Don't

  • Duplicate metric logic in agent instructions
  • Add tools no golden question needs
  • Ship without testing an out-of-scope question

Create and manage agents · Agent evaluations

MCP + Claude Code

  • Expose only the agent, not raw SQL. It carries your instructions, semantic view and access rules.
  • Write the tool description for the AI client: what it can answer and what it can't. That's what Claude reads to decide when to call it.
  • Use a short-lived, role-restricted token, keep it in an environment variable, and never paste it into a chat or a file.
  • Test with curl first, then connect Claude Code. It tells you quickly whether the problem is the token, the URL or the client.

Teamwork on the day

  • Work in parallel: the modeller on the semantic view, the agent builder on the agent and MCP, the tester on questions and expected answers.
  • One shared workspace, one builder. Everyone edits; your edits are a draft until you click Publish. Publish, then tell the driver, who builds. Two people building at once overwrite each other.
  • Changed it in the UI? Say so in the team, then the driver runs export_yaml and pastes it into the file before the next build. Otherwise the build replaces your UI change.
  • Timebox: if something is stuck for 15 minutes, ask a facilitator or simplify.
  • Write down what you skipped in NEXT_STEPS.md. That's your backlog tomorrow.
