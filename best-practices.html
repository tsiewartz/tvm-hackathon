Best practices

What separates a demo that impresses from an MVP people trust. Distilled from Snowflake's guidance and from real customer projects.

The top 10

#PracticeWhy
1Start from real questions, not from the tablesTen golden questions give scope, a test set and a demo script all at once
2Start small: one domain, 3–10 tables, a star schemaEasier to debug, and accuracy is higher
3Describe everything in business languageDescriptions are the biggest single driver of accuracy
4Define metrics in the semantic view, not in promptsOne definition, reused by every agent, BI tool and notebook
5Define every relationship your questions needThe agent won't guess joins
6Add verified queries last, from real questionsThey optimise a good model; they don't rescue a weak one
7Keep synonyms rare, only for internal termsModern models already know the common ones, and extra synonyms just add noise
8Test after every change against your golden questionsFixes have side-effects
9Let governance flow through: policies on tables, not in promptsThe AI layer inherits RBAC, masking and row access
10Everything as code: dbt + Git + CIReview, history, rollback and repeatable deploys

Semantic views

✓ Do

  • Ask "how would I explain this to a business stakeholder?"
  • Explain TVM-specific terms, abbreviations and legacy names
  • Use one semantic view per domain or use case, each with a clearly distinct description
  • Use metrics for rates, averages and distinct counts
  • Use module_custom_instructions.sql_generation for defaults: period, currency, fiscal calendar
  • Use module_custom_instructions.question_categorization to decline or clarify
  • Use Cortex Search for free-text values with many distinct values (titles, names)

✗ Don't

  • Build one "all tables" semantic view
  • Include every column
  • Auto-generate synonyms
  • Patch a weak model with dozens of verified queries
  • Start in a domain that needs 100% accuracy
  • Put real PII in sample values (they aren't masked)
  • Use Cortex Search on numbers, dates or long free-text fields

Agents

✓ Do

  • Name the audience and the decision in the instructions
  • Make tool descriptions specific: they're the routing signal
  • Have the agent state its assumptions (period, filters)
  • Set a budget (seconds and tokens) and a warehouse with a timeout
  • Evaluate with a dataset of golden questions

✗ Don't

  • Duplicate metric logic in agent instructions
  • Add tools no golden question needs
  • Ship without testing an out-of-scope question

Cortex Agent evaluations

dbt

  • Layering: sources → staging → marts → semantic/ → ai/. AI objects are just the last layer of the DAG.
  • Use ref() everywhere, including inside agent and MCP specs, so dbt builds in the right order.
  • Test the marts under your semantic view (unique, not_null, relationships). The agent is only as good as the data under it.
  • Manage grants in code (dbt meta or post-hook), not by hand.
  • Use one target schema per team or developer in dev, and promote through CI.

Best practices for developing & deploying semantic views

Teamwork on the day

  • Work in parallel: the modeller works on the semantic view, the agent builder on the agent and MCP, the tester on questions and expected answers.
  • One driver builds, small and often. Teammates change things in the UI and the driver exports them into the project before the next build. After today the project goes into TVM's Git repo with review.
  • Timebox: if something is stuck for 15 minutes, ask a facilitator or simplify.
  • Write down what you skipped in NEXT_STEPS.md. That's your backlog tomorrow.

Common pitfalls

SymptomLikely causeFix
Wrong numbers, plausible SQLMetric not defined, so the AI invents oneAdd the metric with a precise description
"Can't answer" on join questionsA missing relationshipAdd it under relationships: (the right table needs a primary_key)
Wrong time periodNo default ruleAdd a sql_generation rule for default periods
Text filter returns 0 rowsThe value is spelled differently in the dataAdd a Cortex Search service on that dimension
Agent picks the wrong toolVague or overlapping tool descriptionsMake descriptions distinct, using words from your questions
Scope creep"Just one more table"Back to the golden questions. Everything else goes on the backlog
