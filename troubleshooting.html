Troubleshooting

The most common problems, and how to fix them fast.

Preflight & workspace

A preflight check is RED

First check the 3 values at the top (team number, marts database, marts schema), and that your dev role and warehouse are selected. If the row says Admin fix A/B/C, a facilitator sends the matching lines from the bottom of preflight.sql to TVM's admin.

My teammate doesn't see my change

Edits are a private draft until you click Publish on the file. Uploads, renames and deletes are visible straight away.

I can't see the team's shared workspace

Switch to your dev role in the user menu (bottom left). The workspace list follows that role, not the role in a SQL file.

Upload doesn't keep the folders

Use + Add New » Upload Folder and pick the whole unzipped team_n folder, not the zip and not the files inside it. You should see team_n/dbt_project.yml. If files landed loose, create the folder and move them in (dragging works inside the workspace), keeping models/ and macros/.

No Profile / dbt controls in the bottom panel

Open a file inside team_n/. The profile list comes from team_n/dbt_projects_profiles.yml: paste row 8 of the preflight into it.

Semantic views

YAML error when building the semantic view

The model body is YAML only, no CREATE. Check the indentation: two spaces per level, list items start with - . Most errors are one misaligned line.

invalid identifier in a verified query

Verified-query SQL uses the semantic view's logical names (FROM mart, period), not the physical table and columns. Use sql: | so quotes need no escaping.

Relationship error: referenced key

The table in right_table needs primary_key: {columns: [...]} (or unique_keys) on the join column.

Descriptions from schema.yml don't show up

They don't reach the semantic view. Put description: on the table, dimension, fact or metric in the model's YAML.

Agents

The answer looks wrong

Ask "show me the SQL". Usually the fix is in the semantic view: a missing metric, a vague description, a missing relationship, or a default-period rule. Rebuild, then ask again.

Agent build fails with a privilege error

Your role needs CREATE AGENT on the schema (automatic if dbt created it), and the Cortex database roles (SNOWFLAKE.CORTEX_USER / CORTEX_AGENT_USER).

Answers time out

Raise orchestration.budget.seconds moderately. Then look at why the SQL is slow: a missing filter, or a fact table that's too large. Make sure the tool's execution_environment warehouse is running.

Snowflake CoWork

My agent doesn't show up in CoWork
  • Run SHOW SNOWFLAKE INTELLIGENCES;. If there's a CoWork object, the agent must be added to it: set cowork_object in the agent's meta (needs MODIFY), or ask Astrid to run ALTER SNOWFLAKE INTELLIGENCE … ADD AGENT.
  • Your current role needs USAGE on the agent, its database and its schema.
  • CoWork uses your default role. Switch roles in CoWork, or ask for your default role to be set.
The agent answers in Snowsight but errors in CoWork

CoWork runs as the user's role and default warehouse. That role needs USAGE on the agent, SELECT on the semantic view and SELECT on its tables, and the user needs a default warehouse. Masking and row policies apply, so different numbers can be correct.

MCP & Claude Code

MCP server shows "failed" in /mcp
  • The hostname needs hyphens: my-org-my-account.snowflakecomputing.com
  • Check the database, schema and MCP server name in the URL (upper-case is fine)
  • Test with curl: curl -s -X POST "$MCP_URL" -H "Authorization: Bearer $SNOWFLAKE_PAT" -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
PAT is invalid / network policy

PATs are only accepted from IPs allowed by TVM's network policy. Make sure you're on the TV4 network or VPN. Still failing? Ask Astrid Berghult (TVM, today's Snowflake admin) to check the policy. Expired? Create a new token, then remove and re-add the MCP server in Claude Code.

Agent tool: Text parameter is required

When calling the agent tool directly over MCP, the argument is named text. Claude handles this automatically.

Cost

Queries hang or the warehouse is suspended

The daily credit cap may have been hit. That's the guardrail working, so tell a facilitator.
