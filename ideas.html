Level up your MVP

Pick ideas that make your golden questions score better, not the coolest feature. Every snippet uses the same YAML as your skeleton; paste it into the right model and build. Changed something in the UI instead? export_yaml, paste, build.

Quick wins

Do these first. Each fixes a common wrong answer.

15 min Starter questions in CoWork

Why: New users don't know what to ask. Starter questions show what the agent is good at, and they always work.

How: Add 2–3 golden questions as verified queries in sv_team_{{N}}.sql and mark them as onboarding questions. Easiest: add them in Semantic Studio, test them there, then run export_yaml and paste.

verified_queries:
  - name: amount_per_month
    question: 'What was the total amount per month this year?'
    use_as_onboarding_question: true
    sql: |
      -- the SQL you tested in Semantic Studio

Docs: Verified queries

10 min Business rules and polite refusals

Why: Fixes the most common wrong answers (wrong period, wrong currency) and stops questions the agent shouldn't answer, without touching the data.

How: Add module_custom_instructions at the top level of your semantic view YAML.

module_custom_instructions:
  sql_generation: |
    If no period is given, use the last 12 complete months and say which months.
    Amounts are in EUR. Round money to whole numbers.
  question_categorization: |
    Decline questions about individual subscribers or named people.
    If the question has no market, ask whether it is Sweden, Finland or both.

Docs: Custom instructions

15 min Synonyms and sample values

Why: Users say "Finland", the column says FI. Synonyms and sample values let Analyst map business words to the right column and value.

How: On the dimensions people filter by, add synonyms and the values they use. is_enum: true means "these are all the values".

      - name: COUNTRY
        synonyms: ['market', 'country']
        description: 'Market: SE = Sweden, FI = Finland'
        expr: mart.country
        sample_values: ['SE', 'FI']
        is_enum: true

5 min Charts on request

How: Ask "…show it as a line chart" in CoWork. To get charts by default, add a line to the agent's response instruction.

instructions:

Stretch

When the basics score 7/10 or more.

30 min A second table, joined

Why: Most real questions need a dimension table (plan, user, content). A relationship lets Analyst join it correctly, instead of guessing.

How: Add the second table with a primary_key, then a relationship from the fact table to it. List the table in _marts_sources.yml first.

  - name: PLANS
    base_table: {{ base_table(source('tvm_marts', 'dim_plans')) }}
    primary_key:
      columns: [plan_id]
    dimensions:
      - name: PLAN_NAME
        expr: plans.plan_name
relationships:
  - name: mart_to_plans
    left_table: MART
    right_table: PLANS
    relationship_columns:
      - left_column: plan_id
        right_column: plan_id

Docs: Relationships · Modeling best practices

20 min Rates and ratios as derived metrics

Why: Churn rate, conversion rate, average revenue per user: define the ratio once, so the agent never divides the wrong way.

How: Add a view-level metrics: block (same level as tables:) that combines table metrics.

metrics:
  - name: AVERAGE_AMOUNT_PER_ROW
    description: 'Total amount divided by number of rows'
    expr: mart.total_amount / NULLIF(mart.row_count, 0)

Docs: Derived metrics

30 min Fuzzy matching on titles or names

Why: "Show me Solsidan" fails if the title is stored as "Solsidan S08". A Cortex Search service on the column finds the right value.

How: Create a search service over the distinct values (worksheet, as your dev role), then point the dimension to it.

CREATE CORTEX SEARCH SERVICE {{DEV_DB}}.{{SCHEMA}}.TITLE_SEARCH
  ON title WAREHOUSE = {{DEV_WH}} TARGET_LAG = '1 day'
  AS SELECT DISTINCT title FROM <MARTS_DB>.<MARTS_SCHEMA>.<content_table>;

-- in sv_team_{{N}}.sql, on the TITLE dimension:
        cortex_search_service:
          service: TITLE_SEARCH
          literal_column: TITLE
          database: {{DEV_DB}}
          schema: {{SCHEMA}}

Docs: Cortex Search · YAML specification

45 min A second domain

Why: Keep each semantic view focused (subscriptions, viewing) and let the agent pick. Smaller views give more accurate SQL than one huge one.

How: Add sv_team_{{N}}_viewing.sql as a copy of your skeleton, then a second analyst tool in the agent. The tool descriptions decide which one it uses.

tools:
  - tool_spec:
      type: "cortex_analyst_text_to_sql"
      name: "viewing"
      description: "Viewing sessions: minutes watched by content type, device and day"
tool_resources:
  viewing:
    semantic_view: "{{ ref('sv_team_{{N}}_viewing') }}"
    execution_environment:
      type: warehouse
      warehouse: "{{ target.warehouse }}"

How: Put your golden questions and expected answers in a table, then run a Cortex Agent evaluation on it. Report the score in the demo.

60 min A custom tool: "what if?"

Why: Lets the agent calculate, not just look up. E.g. "what happens to MRR if we raise the price by 10%?"

How: Write a stored procedure (CoCo can draft it, test it with CALL). Add it in the agent editor under Tools » Custom tools, then run export_yaml so the tool lands in agent_team_{{N}}.sql. Grant USAGE on the procedure to the dev role.

CREATE OR REPLACE PROCEDURE {{DEV_DB}}.{{SCHEMA}}.SIMULATE_PRICE_CHANGE(PCT FLOAT)
RETURNS VARCHAR LANGUAGE SQL EXECUTE AS CALLER
AS $$ ... $$;

60 min Documents plus data

Why: The data says what happened. A pricing policy or campaign brief says why. With both, the agent can explain.

How: Upload a few PDFs to a stage, parse them, build a Cortex Search service on the text, and add it as a cortex_search tool next to your semantic view.

Docs: Cortex Search · Create & manage agents

30 min Same metrics in a dashboard

Why: One definition for both the agent and the dashboard, so the numbers always match.

How: A downstream dbt model that queries your semantic view. dbt builds it after the view.

{{ config(materialized='table') }}
SELECT * FROM SEMANTIC_VIEW({{ ref('sv_team_{{N}}') }}
  METRICS mart.total_amount
  DIMENSIONS mart.period)
